# 🌰栗子的指令 (ST-UserInstructions)

给 SillyTavern 加一个「我自己写死的指令」面板：把必须让 AI 记住的东西写进去，**每一轮生成前自动注入**，不用在对话里反复强调。

典型用途：

- 「当前节点：乐队尚未成立，相关后续事件一律不得提及」
- 角色状态速查、关系阶段
- 硬性禁令（不许替 {{user}} 决定行动、不许 OOC）
- 写作风格（视角 / 长度 / 节奏）
- 久没出现就提醒一次的时间线约束

---

## 安装

**方式一（推荐）**：把 `ST-UserInstructions` 整个文件夹放进

```
SillyTavern/public/scripts/extensions/third-party/
```

**方式二**：SillyTavern → 扩展（插件）面板 → `Install extension` → 填本地路径或仓库地址。

放好后**刷新页面（F5）**，在扩展抽屉里会多出一栏「**指令**」。

> 无需 npm / 构建，纯前端 ES module。

---

## 界面

| 位置 | 说明 |
| --- | --- |
| 启用本插件 | 总开关。关掉后所有指令都不再注入，但内容都保留 |
| 加强前缀 | 注入时加在内容前面的抬头，默认 `【必须遵守的设定】` |
| 新建指令 | 新建一条。当前停在「本聊天」标签页时，会建到本聊天里 |
| 模板… | 选一个模板直接生成条目，带 ★ 的是你自己存的 |
| 管理模板 | 删掉不用的模板（内置的也能删，随时可恢复），或给自建模板改名 |
| 一键强化 | 把所有条目改成「聊天内深度 0 + system + 加强前缀」 |
| 全部启用/停用 | 一键切换 |
| 导出 / 导入 | JSON 备份、跨设备搬运、分享给别人 |
| 清空当前标签 | 清空当前标签页可见的条目 |
| 标签页 | 全部 / 全局 / 本聊天 |
| 底部「本回合生效」 | 点开可看到**这一轮实际塞进去的原文**和 token 估算 |

每张卡片：

- 左侧绿点 = **本轮会注入**（鼠标悬停看原因：`always` / `hit` / `sticky:1` / `turn:6`）
- 勾选框 = 单独启用/停用该条
- `▲ ▼` = 上移 / 下移（同一作用域内）
- `⧉` = 复制这条
- `☆` = **把这条存成模板**（弹窗问名字），以后在「模板…」里一键套用
- `✕` = 删除

## 三种触发方式

| 方式 | 行为 | 适合 |
| --- | --- | --- |
| **常驻** | 每轮都注入 | 世界观、时间线、硬性禁令、写作风格 —— **你 90% 的需求用这个** |
| **关键词** | 最近消息命中关键词才注入；命中后按「黏着轮数」继续注入若干轮 | 「提到某个词时才需要提醒」的约束 |
| **每 N 轮** | 每 N 条用户发言注入一次 | 低频但重要的提醒，省 token |

关键词细节：

- 分隔符支持换行、中英文逗号、分号、`|`
- 匹配方式：任一 / 全部 / **正则**（写 `/乐队.*成立/i` 这样）
- 扫描范围：最新一条用户消息（默认）/ 最近 N 条消息 / 整个聊天
- **黏着轮数**：命中那一轮起，额外再注入几轮。设为 `2` ≈ 命中当轮 + 之后 2 轮，用来解决「说一次，过几轮又忘」

---

## 注入位置怎么选（关键）

| 位置 | 效果 |
| --- | --- |
| **聊天内 @ 深度 0，system** | **最不容易被忽略**。紧贴最新一条消息之前，等效于「上一轮刚跟你说过」 |
| 聊天内 @ 深度 2 | 稍靠前一点，也很强 |
| 系统提示词内 / 最前 | 离当前对话远，长上下文里容易被稀释 |

深度 `0` = 紧贴最新消息，数字越大越靠前。位置选「聊天内」时才需要填深度，也只有此时能选角色（system 最硬）。

> 觉得 AI 老是「不读」时，先点 **一键强化**。

---

## 作用域：全局 vs 本聊天

- **全局**：存在 ST 的 `settings.json`，所有角色、所有聊天都生效。适合写作风格、通用禁令。
- **本聊天**：存在**聊天文件**里，跟着这条聊天走。适合「当前节点」「当前角色状态」这类**每个档都不一样**的内容。

同一张角色卡开两条线（比如「乐队未成立」和「乐队已成立」），用「本聊天」最合适，互不干扰。

---

## 和 ST 自带功能的关系

ST 本身也能做到类似效果（作者注释、世界书的**常驻**条目、`/inject` 指令），本插件不冲突，可以共存：

- 比作者注释：多了**多条独立条目**、关键词黏着、每 N 轮、导入导出、实时生效预览
- 比世界书：不用配触发键，也不会被世界书扫描顺序影响；面板就在扩展里，改一句话不用进世界书编辑器
- 想用斜杠指令的话 `{{inject}}`（ST 原生）依然可用，两者互不干扰

---

## 数据存放

| 作用域 | 位置 |
| --- | --- |
| 全局条目 + 插件设置 | ST 数据目录 `default-user/settings.json` → `extension_settings.user_instructions` |
| 本聊天条目、黏着计数 | 聊天文件的 `chat_metadata.user_instructions` |

删除扩展文件夹不会丢数据，但重新安装后条目会照旧读回来。**迁移前建议先导出**。

## 开发 / 测试

```
node test/suite.test.mjs   # 31 项：模板管理 + 核心逻辑 + 假 ST 上下文跑真实注入管线
```

测试里「注入管线」那段会临时设置 `globalThis.SillyTavern` / `document` / `jQuery` 桩，再用 `import('../index.js?boot=1')` 触发一次真实启动，所以能覆盖黏着递减、旧 key 清理、切换聊天不残留这些只有跑起来才暴露的问题。

`index.js` 的纯逻辑部分（`createEntry` / `matchKeywords` / `evaluateEntry` / `composeInjection` …）不依赖任何浏览器或 ST 全局，可以直接 import 出来测；ST 相关代码只在检测到 `SillyTavern` 全局后才启动。

依赖的只有 ST 官方稳定 API：`SillyTavern.getContext()` 里的 `setExtensionPrompt` / `extensionSettings` / `chatMetadata` / `eventSource`。无 jQuery 插件依赖，无网络请求。

## 已知限制

- 「每 N 轮」按**用户发言条数**计数，编辑/删除历史消息后轮号会跟着变
- 黏着计数存在聊天文件里，如果你在生成过程中强行刷新页面，那一轮可能不计数
- 注入内容会计入上下文长度，长条目记得看底部的 token 估算
- 一个条目一条注入 key，条目非常多（上百条）时提示词会被切得很碎，建议合并同类项
